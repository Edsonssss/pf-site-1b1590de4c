# Страница правки портфеля — `edit.html`

Отдельная страница для правки **всех позиций** портфеля: акции, фонды, кэш,
заблокированные активы и семейный счёт. Все сводные показатели пересчитываются
автоматически по формулам `auto_update.py` (строки 105–124) — 1:1.

Код вашего репозитория не изменяется: `edit.html` — новый самостоятельный файл,
работает как по HTTP (GitHub Pages), так и локально через `file://`.

---

## 1. Установка

Положите `edit.html` в корень репозитория — рядом с `index.html`,
`portfolio_data.js` и `portfolio_data.json`:

```
pf-site/
├── index.html            ← без изменений (правки ниже — опциональны)
├── edit.html             ← НОВЫЙ файл
├── portfolio_data.json
├── portfolio_data.js
└── ...
```

Данные страница берёт **сначала из `portfolio_data.json`** (источник истины —
именно его вы коммитите после правок); при недоступности (например, при
открытии из файловой системы, где `fetch` запрещён) подключается
`portfolio_data.js`, затем встроенная копия. Это защищает от рассинхрона:
`portfolio_data.js` генерируется конвейером и может временно отставать от
JSON, если после коммита не запускать workflow. Источник виден в шапке
страницы («данные: …»).

## 4. Как пользоваться

1. Откройте `edit.html` — данные подгрузятся из `portfolio_data.js`.
2. Правьте количество в любой строке (акции, фонды), суммы кэша и семейного
   счёта, количество заблокированных бумаг. Изменённые строки подсвечиваются,
   под полем показывается «было N».
3. Удаление — кнопка **✕** в строке:
   - позиция **из репозитория** — мягкое удаление: строка зачёркивается,
     её можно вернуть кнопкой **«вернуть ↺»** (до самой выгрузки JSON);
   - **черновая** позиция (добавленная вами) — удаляется сразу и насовсем,
     никакой строки-надгробия в черновике не остаётся.
4. Добавление — строка «+ Добавить акцию/фонд» внизу каждой таблицы. Тикер
   или ISIN введёте — цена подтянется с MOEX ISS автоматически: акции — доска
   TQBR, биржевые фонды — TQTF, облигации — доски TQCB/TQOB (котировка
   «% от номинала» пересчитывается в рубли за бумагу с НКД); если MOEX
   недоступен, введите цену вручную.
5. Таблица акций отсортирована **по названию бумаги** (по-русски), не по
   тикеру; нумерация `n` и порядок в выгружаемом JSON при этом не меняются.
6. Черновик **автоматически сохраняется** в браузере (localStorage, ключ
   `pf_manual_edits_v1`) и переживает перезагрузку. Хранится только дельта
   правок, поэтому после утреннего обновления цен черновик ложится на свежие
   данные. При каждой загрузке черновик **самоочищается**: устаревшие записи
   (позиция-надгробие, правка, с которой репозиторий уже согласился после
   публикации, дублирующая базу правка) снимаются сами — отдельный сброс
   не нужен.
7. Кнопка **«⬇ Скачать portfolio_data.json»** выгружает полный JSON с
   применёнными правками и пересчитанной сводкой. Далее — стандартный цикл
   публикации: закоммитить файл → запустить workflow (Run workflow) → конвейер
   пересоберёт `portfolio_data.js`, встроенную копию и Excel.
   Кнопка **«⬇ .js»** — то же самое сразу в виде `portfolio_data.js`, для
   локального просмотра без запуска конвейера.
8. **«↺ Сбросить всё»** возвращает данные к состоянию репозитория и стирает
   черновик.

До публикации главная страница (`index.html`) показывает данные **без правок** —
это осознанное решение из утверждённого макета.

## 5. Что пересчитывается автоматически

| Показатель | Формула (источник — auto_update.py) |
|---|---|
| Стоимость позиции | `qty × цена` (стр. 61 / 103) |
| stocks_value, funds_value | сумма стоимостей (стр. 107–108) |
| cash_value | поле «Кэш» на странице (в конвейере не пересчитывается — здесь исправлено) |
| total_value | акции + фонды + кэш (стр. 109) |
| shares_pct | доли акций/фондов/кэша (стр. 110–112) |
| weighted_upside_pct | взвешенный потенциал по позициям с прогнозом (стр. 113–114) |
| dividends_12m_gross | Σ (дивдоходность × цена × qty) — оценка, точность ограничена округлением дивдоходности до 0,1% (стр. 115) |
| dividends_12m_yield_pct | к итогу портфеля (стр. 116) |
| upcoming_dividends_* | переносятся из файла (стр. 117–118) |
| blocked_value_usd/rub | `qty × цена$ × курс ЦБ` из `macro.usd_rate_cbr` (стр. 119) |
| total_including_blocked | итог + заблокированные (стр. 120) |
| family_value, total_family | семейный итог (стр. 123–124) |
| recommendations | счётчик «Покупать/Держать/…» по строкам |

**Не изменяются:** цены (`current_price`, `prev_close`), цели аналитиков,
`history` (динамика остатков), `meta.date` — их обновит утренний прогон после
публикации.

## 6. Заметки и нюансы

- **Дивиденды 12 мес** — знак «≈»: годовая сумма на бумагу восстанавливается из
  дивдоходности (в исходных данных она округлена до 0,1%), возможное отклонение
  до ±0,9 ₽ на весь портфель. Утренний конвейер посчитает точно из
  `dividends_raw.json`.
- **blocked_value_usd** в текущем файле устарел (235,80 $ при фактических
  243,06 $): страница пересчитывает это поле корректно, скачанный JSON
  «починит» его в репозитории.
- Удалённые строки помечены `«−тикер»` в статусе изменений; нумерация `n`
  сохраняется как в репозитории (дыры — норма, см. NVTK с n=32), новые позиции
  получают номера с 33.
- Дубликат тикера добавить нельзя — страница предложит править количество в
  существующей строке.
- **Облигации** (можно вводить как тикер, так и ISIN, например RU000A10C5L7 —
  «Селигдар 001Р-04»): цена берётся с доски TQCB/TQOB как % от номинала и
  пересчитывается в рубли: % × номинал + НКД. Два нюанса: (1) утренний
  конвейер цены облигации **не обновляет** (он опрашивает только рынок акций
  TQBR; одна-две «чужие» бумаги в списке ему не мешают — в auto_update.py
  заложен допуск), т.е. цена останется той, что была при добавлении;
  (2) НКД меняется ежедневно, поэтому позицию полезно периодически обновлять:
  удалить строку (✕) и добавить заново — цена подтянется свежая.
- Сортировка отображается по названию; в скачанном JSON порядок позиций
  остаётся прежним, чтобы не создавать шум в git-диффе.
- **Не забывайте про `portfolio_data.js`**: этот файл генерируется конвейером
  из JSON (workflow «Run workflow» или ночной прогон). Если закоммитить только
  JSON — страница правок покажет свежие данные (она читает JSON первым),
  а локальный просмотр через file:// (по `.js`) и встроенная копия в
  index.html обновятся только после запуска конвейера.
- Рекомендация у новой позиции пустая → попадает в «без прогноза», из
  взвешенного потенциала исключается (как FEES/PMSB в конвейере).
- Все браузерные данные остаются локальными; страница не отправляет ничего
  наружу, кроме запроса цен на `iss.moex.com` при добавлении позиций.

## 7. Сверка с API Т-Банка (кнопка «⇄ Сверка с Т-Банком»)

Страница умеет сверять содержимое сайта с реальным портфелем Т-Банка,
полученным через T-Invest API — вместо ручного копирования таблицы из
приложения.

**Откуда берётся выгрузка.** Скрипт `fetch_tbank_portfolio.py` (только
стандартная библиотека Python) обращается к API:

- `UsersService/GetAccounts` → список счетов;
- `OperationsService/GetPortfolio` → позиции: количество, средняя цена,
  текущая цена, НКД, доходность; итоги по классам активов;
- `InstrumentsService/ShareBy|BondBy|EtfBy` → FIGI → тикер/имя, номинал
  (у облигаций цена в API — % от номинала; скрипт пересчитывает в рубли:
  % × номинал + НКД, как и страница).

Результат — `tbank_portfolio.json` с полями `account`, `generated_at`,
`totals`, `positions[]` (тикер, тип, кол-во, цена, стоимость, blocked).

**Запуск локально:**
```bash
export TB_TOKEN="t.xxxxxxxx"            # read-only токен
python3 fetch_tbank_portfolio.py        # → tbank_portfolio.json
```

**Токен (безопасно, в GitHub Environments):**
1. Сайт tbank.ru → Настройки профиля Т‑Инвестиций → карточка «Токены
   T-Bank Invest API» → выпустить токен **«Только для чтения»**.
2. На GitHub: **Settings → Environments → New environment** → имя `tbank`
   → **Add environment secret** → `TB_TOKEN` = токен. Секрет окружения
   доступен только job'ам со строкой `environment: tbank` — торговых прав
   у него нет, срок жизни — 3 месяца с последнего использования.
3. Положите в репозиторий `scripts/fetch_tbank_portfolio.py` и
   `.github/workflows/tbank_sync.yml` (файл прилагается). Workflow ходит
   ежедневно в 08:20 МСК, выгружает портфель и **коммитит
   `tbank_portfolio.json`** в корень репозитория (плюс кладёт в артефакты
   сборки).

**Как сверять на странице.** Кнопка **«⇄ Сверка с Т-Банком»** в панели
инструментов открывает блок сверки; выгрузка подхватывается сама кнопкой
**«⤓ Взять с сайта»** (или выберите файл вручную — работает и по `file://`).
Дальше:

- **расхождения по количеству** → кнопка «✓ исправить на N» у каждой
  строки и «✓ Исправить все количества (N)» разом;
- **есть в Т-Банке, нет на сайте** (включая облигации) → «+ добавить в
  черновик» / «+ Добавить отсутствующие (N)»: позиция создаётся сразу с
  ценой из выгрузки, у облигаций — с пометкой про НКД;
- **на сайте есть, в Т-Банке нет** → кнопка «✕ удалить с сайта»
  (вручную по одной — в выгрузке может быть другой счёт);
- позиция, помеченная удалённой, но живая в Т-Банке → «вернуть ↺»;
- **фонды** сопоставляются по тикеру из названия («… (TMON)», «… (BCSD)»);
  ОПИФы без тикера показываются как не сверяемые автоматически;
- **валюта** и **заблокированные иностранные** — только информационно:
  кэш на сайте — это Яндекс Банк, а не брокерский счёт; Barrick и т.п.
  живут в разделе «Заблокировано» вне итога.

**Сверка ИИС (второй счёт).** Скрипт `fetch_tbank_portfolio.py` сам находит
счёт ИИС и сохраняет **`tbank_iis.json`** (workflow коммитит его рядом с
основным). Порядок определения счёта: `--iis <id>` или секрет
`TB_IIS_ACCOUNT` → `type` счёта содержит `IIS` (ACCOUNT_TYPE_TINKOFF_IIS) →
имя счёта содержит «ИИС» → резервно: у счёта в портфеле есть бумаги из
секции `iis` сайта (живой случай 17.11.2026: GetAccounts вернул счёт ИИС
без специального типа — проверка по type ничего не находила; теперь в логе
workflow видны все счёта с их type/name, и выгрузка ИИС всё равно
находится). Если `GetAccounts` вернул только один счёт — токен выпущен для
одного счёта (так устроен API: «метод возвращает только те счета, к которым
у вас есть доступ»); нужен токен с доступом ко **всем** счетам — пере
выпустите его и обновите секрет `TB_TOKEN`. В том же блоке сверки
появляется раздел «ИИС (второй счёт)»:
сопоставление по биржевому тикеру или ISIN (облигации на сайте лежат по
ISIN), кнопки те же — «✓ исправить на N», «+ добавить в черновик» (позиция
создаётся сразу в секции ИИС), «✕ удалить с сайта», «вернуть ↺» и групповые
«✓ Исправить количества ИИС» / «+ Добавить отсутствующие». Файл можно
подложить вручную кнопкой «📁 tbank_iis.json (ИИС)» — работает и по
`file://`. Если основного файла нет, а ИИС-файл есть — сверяется только ИИС.

**Фонды из выгрузок (TMON на двух счётах).** Фонды сверяются в блоке
«Фонды»: фонд с «· ИИС» в названии — против `tbank_iis.json`, остальные —
против `tbank_portfolio.json` (тикер из скобок названия; API отдаёт фонды
с «@» — «TMON@» → «TMON», сравнение это учитывает). TMON существует в двух
строках: «… (TMON) · осн» и «… (TMON) · ИИС» — правка количеств кнопкой
«✓ исправить» идёт в разделе «Фонды», позиции ИИС-выгрузки, живущие в
фондах, из ИИС-сверки исключены (подсказка в заголовке ИИС). Фонд, которого
нет на сайте, добавляется кнопкой «+ добавить в фонды (ИИС)» — черновик
создаётся с количеством и ценой из выгрузки. Позиции ИИС-выгрузки,
совпавшие с секцией ИИС сайта, и бумага осн. выгрузки, совпавшая с секцией
ИИС сайта, расхождениями не считаются. При наличии обеих выгрузок в панели
показывается строка «Итого по Т-Банку: N ₽ (осн. счёт X + ИИС Y)» — сумма
`totalAmountPortfolio` обеих выгрузок.

После применения правок панель сама перечитывает состояние («совпадает ✓»),
дальше — обычный цикл: «⬇ Скачать portfolio_data.json» → коммит → workflow.

## 7.1 ИИС в правке позиций (второй счёт)

Секция «🏦 ИИС (Т-Банк) — второй счёт» редактируется как полноценная часть
портфеля:

- **количество** — правится в строке (с подсказкой «было N»); стоимость,
  доля ИИС, итог портфеля и «Семейный итог» пересчитываются на лету;
- **примечание** — текстовое поле в строке (для «переведено с основного
  счёта…» и пометок про купоны), входит в черновик и в выгрузку;
- **удаление/возврат** — «✕» помечает позицию удалённой (строка-надгробие
  с «вернуть ↺»), как у акций;
- **добавление** — форма «+ Добавить в ИИС: тикер/ISIN, кол-во, цена»:
  цена и название подтягиваются с MOEX ISS (облигации — % номинала + НКД),
  а купоны и цену дальше обновляет ночной конвейер (`auto_update.py`);
- **карточка «ИИС»** на верхней панели и «ИТОГО ИИС» с долей в портфеле;
- в «⬇ Скачать JSON» секция `iis` попадает целиком (без надгробий), а
  формулы сводки (рекомендации, дивиденды 12 м) считаются по обоим счетам.

Сверка ИИС с выгрузкой Т-Банка — см. раздел 7 выше (файл `tbank_iis.json`).
